# Technology map and alternatives

These are defensible explanations of the current design, based on source inspection. They do not mean every alternative was experimentally evaluated during development, or that one technology is universally better.

| Area | Used here | What it does in EventPoint | Common alternatives | Why this fits; what we give up |
|---|---|---|---|---|
| Language | TypeScript | Types for React, API services and shared contracts | JavaScript; Java/Kotlin; Python | One language across the repository and earlier type errors. Types disappear at runtime, so input validation is still required. |
| Frontend | Next.js 14 + React 18, App Router | Routes, server-rendered public pages and interactive client components | React + Vite; Angular; Vue/Nuxt | Routing and server/client rendering in one framework. More rendering and caching concepts than a simple SPA. |
| Styling | Tailwind CSS + shared custom CSS, Lucide icons | Utilities, themes, responsive layout and consistent surfaces | CSS Modules; MUI; Bootstrap | Custom visual control and shared styles. We own accessibility and consistency instead of receiving a complete component system. |
| Repository | npm workspaces + Turborepo | Shared packages and build/lint/type-check/test orchestration | Nx; pnpm workspaces; separate repositories | Supports coordinated packages with task caching. Shared changes can affect several apps; build tooling does not make them microservices. |
| Backend | Node.js + Express 4 | HTTP routes, middleware and services | NestJS; Fastify; Next.js route handlers | Explicit request flow and a separately deployed API. Express requires us to structure validation, errors and authorization ourselves. |
| Communication | REST / JSON over HTTP | Browser-to-API requests | GraphQL; tRPC; gRPC | Direct resource endpoints fit this product and external integrations. More endpoints and potential over/under-fetching than tailored graph queries. |
| Validation | Zod in shared validation package | Validate untrusted request bodies and filters | Joi; Yup; class-validator; JSON Schema/Ajv | Runtime validation with TypeScript inference and shared contracts. Shared schemas still need deliberate versioning. |
| Database | PostgreSQL; deployment uses Neon | Related users, organizers, events, bookings, payments and tickets | MySQL; MongoDB; managed Firestore | Foreign keys, joins and transactions fit the relational booking model. MongoDB also has transactions; the choice is about this data model and query needs, not “MongoDB cannot transact.” |
| Data access | Prisma + migrations + selected raw SQL | Typed CRUD, schema changes and advanced search queries | Drizzle; TypeORM; SQL/pg | Productive typed access, while raw SQL handles specialized search. Generated SQL, transaction timeouts and connection usage still need understanding. |
| Inventory | PostgreSQL transactions + conditional updates | Reserve available ticket quantities and reverse expired reservations | Row locks; optimistic versioning; durable queue serialization | A guarded decrement checks availability inside the transaction. No distributed lock service is needed for this path. Explain race handling rather than claiming unconditional “exactly once.” |
| Authentication | JWT access token, rotating refresh sessions, Argon2id; Google OAuth | Sign-in, password verification, refresh/logout and Google accounts | Database session cookie; Auth.js; Clerk; Auth0 | Demonstrates the auth lifecycle directly. Access tokens are accessible to frontend code; only the refresh cookie is HttpOnly. Discuss the XSS/session trade-off honestly. |
| Authorization | Server middleware + role and ownership checks | Restrict admin actions and organizer-owned resources | Policy engines; ABAC; external identity permissions | Roles fit attendee/organizer/admin access, with ownership checks for individual resources. Hiding a UI button is not security. |
| Cache | Redis through ioredis | Selected public reads, TTLs and invalidation; AI guards also have cache-backed controls | In-process LRU; Memcached; CDN caching | Can share cached state across instances. Redis failure falls back to authoritative reads; cache is not the ticket-stock database. Verify deployment configuration before claiming a hit rate. |
| Search | PostgreSQL full-text search + structured filters and pagination | Search words, category, city, date, price and venue | Elasticsearch/OpenSearch; Meilisearch; Algolia | Keeps search near the data at this catalog size. Larger-scale or typo-heavy discovery can justify a dedicated engine after measurement. |
| AI generation | Groq chat-completions API; configurable model profiles | Interpret conversation, choose filters and generate grounded replies | Gemini API; OpenAI API; another hosted or local model | Existing integration uses configurable model tiers and bounded error/quota handling. Do not claim a provider is always cheapest or faster without current measurements. |
| Semantic retrieval | Transformers.js / ONNX, local MiniLM encoder | Turn mood/event text into normalized 384-dimensional embeddings | Hosted embeddings; larger local encoders | No per-request embedding-provider call. CPU, startup download, inference time and memory remain real costs. |
| Vector storage | PostgreSQL float arrays and exact similarity scoring | Store event vectors, source timestamps and hashes | pgvector + ANN indexes; Pinecone; Qdrant; Weaviate | Avoids another vector service for a small catalog. Exact scans are not a large-scale ANN index and should be profiled as data grows. |
| RAG evidence | Text chunks, BM25 lexical scoring, semantic reranking and reciprocal rank fusion | Select concise policy/FAQ/event evidence for generation | Vector-only retrieval; keyword-only retrieval; LangChain/LlamaIndex pipelines | Combines exact terms and meaning with a bounded evidence budget. There are two paths: event discovery and passage retrieval; their rankings are not identical. |
| Payments | Razorpay order/verification/webhooks/refund handling | Coordinate provider payment state with booking state | Stripe; Cashfree; PayU | Fits the INR-focused integration. Browser success is not final proof: server verification, webhook signatures and replay handling matter. Showcase payment records do not prove real charges. |
| Media | Cloudinary with multiple configured providers | Upload and deliver event/category images | S3 + CDN; ImageKit; Supabase Storage | Existing upload/transformation infrastructure avoids building media delivery. Need provider limits, URL ownership and failure handling. |
| Email | Brevo HTTP API | Transactional messages when configured | SES; SendGrid; Resend; SMTP/Nodemailer | One provider integration; delivery is an external failure boundary. Creating a database record does not prove email delivery. |
| Maps | React Leaflet + OpenStreetMap | Venue coordinates, location map and directions entry points | Google Maps; Mapbox | Adequate for basic venue mapping. Tile policies, attribution and production usage limits still apply; no API key is not a promise of unlimited free infrastructure. |
| Digital tickets | qrcode + browser jsQR/camera APIs | Encode tickets and scan QR codes for validation | ZXing; html5-qrcode; hosted barcode services | Browser-based scanning fits the ticket workflow. Camera permissions, secure context and server-side ticket validation are separate concerns. |
| Background work | SchedulerManager in API process | Expire stale bookings; monitor media usage | BullMQ workers; external cron; managed job scheduler | Small operational footprint. Process restarts/sleep and multi-instance overlap require thought; the local overlap guard is not a distributed lock. |
| Quality | ESLint, TypeScript, Jest, live-PostgreSQL integration suite, GitHub Actions | Check source and enforce the CI pipeline | Vitest; Playwright/Cypress E2E; other CI systems | Different checks catch different problems. One failed step fails the combined job; passing unit tests does not prove production behavior. |
| Deployment | Vercel frontend, Render API, Neon database, custom domain/DNS | Host applications and connect eventpoint.dev | AWS/Azure/GCP; Railway/Fly.io; self-hosting | Fits the current deployment setup with fewer services to operate directly. Cold starts, network hops, connection limits and independent deployment states still matter. |
| Observability | Structured logs/request IDs; Sentry hooks | Trace errors and correlate a request | OpenTelemetry; Datadog; Grafana stack | Existing hooks are useful, but source integration is not proof that every deployment has monitoring enabled or full distributed tracing. |
